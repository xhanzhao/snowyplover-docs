Your first animation

In about ten minutes you will fly the camera through three saved views of your model and export the flight as an MP4. You need a Rhino model, SnowyPlover and ffmpeg (see Install).

1. Save the keyframes as Named Views

In Rhino, frame the model the way the animation should start and run NamedView › Save. Name it View 1. Move the camera, save View 2, then View 3. These are the keyframes the camera will fly through, in order.

Keep the same viewport projection (perspective or parallel) for all three views. Mixing them makes the camera jump.

2. Read the views into Grasshopper

Add a Panel, type the three names on separate lines, and connect it to the namedViews input of [[Get Camera From Named Views]]. Its camera output now holds three cameras. If you change a Named View later, click Update on the component to read it again.

names = panel "View 1\nView 2\nView 3"
nv    = GetCameraFromNamedviews

names -> nv.namedViews

3. Interpolate between them

Add [[Animate Keyframes]] and wire the cameras into cameras. Add a Number Slider from 0 to 1 and a Number parameter named t as the t hub, then wire slider → hub → t.

Add [[Apply Camera]], wire camera into it, and click its button so it reads Active. Now drag the slider: the Rhino viewport flies from View 1 to View 3.

names = panel "View 1\nView 2\nView 3"
nv    = GetCameraFromNamedviews
s     = slider 0.35 label="preview"
hub   = param Number "t"
key   = AnimateKeyframes [cameras, t, mode]
cam   = ApplyCamera

names -> nv.namedViews
nv.camera -> key.cameras
s ~> hub
hub ~> key.t
key.camera -> cam.camera

Two settings shape the flight:

  • mode: right-click the component and pick Smooth for a curved path through the camera positions, or leave it Linear for straight segments. With Smooth, curvature (0 to 3) controls how wide the curves swing.
  • durations: one weight per segment. With three views there are two segments; 1, 2 spends twice as long on the second one.

The camPath and camFOV outputs preview the path and the view frame in Grasshopper, which helps when the camera does something unexpected.

4. Export the frames

Add [[View Capture Driver]]. Set totalDuration to the length you want in seconds (try 6), fps to 30, and path to an empty folder such as D:\anim\shot01.

Now move the hub over to the exporter: disconnect the slider from the hub and connect master Time instead. Click Export Frames. The component counts the frames as it saves them (6 s × 30 fps = 180 frames). Click again to stop early.

names = panel "View 1\nView 2\nView 3"
nv    = GetCameraFromNamedviews
key   = AnimateKeyframes [cameras, t]
cam   = ApplyCamera
vcd   = ViewCaptureDriver [totalDuration, fps, path]
hub   = param Number "t"
dir   = panel "D:\anim\shot01"
dur   = slider 6 min=1 max=20 label="seconds" digits=0

names -> nv.namedViews
nv.camera -> key.cameras
dur -> vcd.totalDuration
dir -> vcd.path
vcd.masterTime ~> hub
hub ~> key.t
key.camera -> cam.camera

Leave the Rhino window alone while it exports: the frames are captured from the viewport. Set width and height to render at a fixed size such as 1920 × 1080 whatever the size of the viewport.

5. Make the video

Add [[FramesToVideo]], connect the same folder to folder, and click Make Video. With the defaults you get D:\anim\shot01\keyframe.mp4: H.264 at 30 fps, which plays anywhere. The videoPath output gives the file once it is done.

dir = panel "D:\anim\shot01"
fv  = FramesToVideo [folder, frameRate, format]

dir -> fv.folder

If frameRate here does not match the fps you exported with, the video plays too fast or too slow. To make a GIF instead, use [[FramesToGifs]] the same way.
